# 出门啦 · 产品设计说明

## 用户与问题

面向希望低成本探索城市的大学生。依据题目提出的设计假设：活动信息分散，选择同时受天气、预算和同行人数影响；找到活动后，还需要安排路线、约人和记录体验。本雏形未开展独立用户调研，不将这些假设表述为已验证结论。

产品目标是让用户完成一次连贯的周末决策：**找到想去的地方 → 加入周末清单 → 邀请同行 → 打卡 → 分享攻略**。

## 产品结构

| 页面 | 核心任务 | 主要设计 |
| --- | --- | --- |
| 发现周末 | 决定去哪玩 | 城市、分类、预算、天气、人数筛选；关键词搜索；推荐理由；活动详情 |
| 我的周末清单 | 把心动变成计划 | 加入与移除活动；人均及同行总费用参考；分享清单 |
| 找个搭子 | 明确同行安排 | 活动、时间、人数、集合地点、说明；加入与退出；邀请卡 |
| 我的足迹 | 留住体验 | 心情、文字、可选照片；打卡记录与探索统计 |
| 灵感攻略 | 复用和分享经验 | 示例攻略、自写攻略、可直接打开的分享链接 |

## 关键流程

**轻松决定。** 默认给出一组可浏览的活动。用户调整预算或兴趣后立即得到结果；切换雨天时排除户外活动。空结果状态说明原因，并提供放宽筛选的入口。详情展示建议路线、位置与出发提醒，减少在不同页面之间反复查找。

**低门槛同行。** 从活动详情或周末清单发起小队，明确时间、集合地点及人数，再分享邀请卡。页面直接说明组队状态为本机演示，避免把模拟人数当作真实报名。

**形成记录与分享。** 出行后提交文字、心情和可选照片，保存在足迹页；也可以整理成包含路线、花费与小提醒的攻略，通过链接给朋友阅读。

## 设计取舍

- 用规则筛选与明确推荐理由展示匹配过程，优先让用户理解为什么值得去。
- 将预算定义为活动参考费用，餐饮与交通另行考虑，避免把局部费用当成完整出游成本。
- 一份周末清单限定同一城市，避免生成难以执行的跨城活动组合。
- 使用轻量的本机存储与链接分享，缩短首次体验路径；不将其包装成真实多人协作。
- 用自然绿、留白与场景配图形成轻松的城市探索氛围，同时保留清晰的操作层级与手机布局。

## 后续迭代

优先接入带更新时间及来源的真实活动、天气数据；随后提供账号与共享小队状态，处理满员、取消和变更通知。路线能力可进一步纳入交通时间、开放时段和总预算。通过实际体验观察筛选后查看详情、加入清单、创建小队及分享的完成情况，再决定优化重点；当前没有对应的用户数据或效果结论。
