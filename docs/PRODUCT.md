# 出门啦 · V3 产品设计说明

## 从题目出发

大学生周末需要的不只是更多活动信息，还要回答：哪个适合自己、一天到底花多少、时间够不够、天气变了怎么办、怎样约朋友一起走。以上是依据题目提出的设计假设，尚未开展独立用户研究，也没有已验证的用户规模或业务效果。

目标路径：**看见具体提案 → 比较少量方案 → 安排行程 → 邀请同行 → 打卡与分享。**

## 产品结构

| 模块 | 帮用户做的决定 | 当前设计 |
| --- | --- | --- |
| 发现周末 | 这个周末可以怎样过 | 首屏给出活动组合、时长和完整费用；主题提案可预览，一句话和筛选可细调 |
| 三步定制 | 选哪份更适合 | “选心情、定预算、留时间”收集条件，最多给两份不同组合，写清理由与取舍 |
| 周末计划 | 何时出发、如何调整 | 时间轴、顺序、全天花费、雨天替代；前置约搭子、分享和打卡，空状态直接进入定制 |
| 找个搭子 | 和谁去、在哪里见 | 日期、集合点、人数和说明；本机加入与退出、邀请快照 |
| 我的足迹 / 灵感攻略 | 如何留下和复用经验 | 文字与照片打卡；打卡可整理为可编辑攻略草稿，保存后再分享 |
| 90 秒体验 | 如何快速理解完整流程 | 临时示例计划和操作导览；退出或刷新后回到原有本机记录 |

## 关键产品选择

**先给具体答案，再邀请用户表达。** 首页用活动组合与含餐饮交通的费用解释产品价值，城市图片承担氛围表达。定制只需三步；结果最多两份，重点比较体验、总花费和时间。只有一份可行方案就显示一份，没有结果则解释限制并提供修改入口。

**硬条件约束结果，软偏好影响排序。** 定制方案须满足所选城市、全天预算和可用时长；雨天排除室外活动。兴趣匹配优先，同行人数仅轻量调整类似方案的顺序，不宣称真实容量或票务匹配。更省钱、少一站或未覆盖的兴趣都直接说明，用户确认采用后才更新计划。

**把一整天的花费算进去。** 定制与计划页合计活动、餐饮和交通，再算同行总额；活动列表仍保留单项预算筛选。转场暂按 25 分钟、演出最早 19:00 估排。餐饮目前只预留费用，未排用餐时段；这些估算不替代地图、营业和场次核实。

**变化必须可见、可确认。** 天气预报成功才显示联网数据，限流、断网和超出预报范围均有明确状态，并提供手动情景。雨天替代保留已有室内活动，在预算与时长约束内寻找替换；没有合适替代时可以减少户外站点，完全不可行则保留原计划并提示。确认前展示新费用和时长。分享链接先预览再载入，覆盖已有计划前说明后果。

**让体验和记录有清楚边界。** 产品导览解释设计理由，临时体验模式不覆盖已保存的本机记录；退出还原进入前状态，刷新重新载入原有记录。打卡转攻略只生成可编辑草稿，实际花费留为“待补充”，由用户保存后再分享。普通记录支持 JSON 备份和确认恢复，分享内容是快照，不是实时多人协作。

## 范围与后续

当前覆盖上海、杭州、北京的示例活动；天气来自 Open-Meteo，其余推荐、解析、排程在本地运行，未调用大模型。无账号、业务后台、真实报名或交易，小队人数为本机演示。AI Coding 用于辅助设计、实现与检查，不能据此推断用户效果。

下一步先接入有来源与更新时间的真实活动，补足营业时段、路程和用餐安排，再建设共享小队状态。验证重点是能否完成选择、读懂总费用、处理天气变化并发出邀请；通过实际体验发现问题后再调整设计。各版本检查证据单独记录在 [验证记录](VERIFICATION.md)。
