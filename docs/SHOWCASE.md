## 先体验一次可修改的规划

下面使用正常模式，会在你确认采用后保存正式计划；只试草稿时，关闭即可保留原计划。

先看界面的运行模式：在线模式会将本轮文字与当前结构化出行条件发送给 DeepSeek，历史未覆盖要求由页面继续保留，避免输入联系方式或私密内容；模型只整理条件，地点与预算、时间约束仍由规划规则核对。网络、额度或格式校验失败时会明确回退本地规则，仍可修改和手动核对。云服务持续在线依赖套餐额度、模型余额和限制，不以一次成功请求承诺长期可用。

1. 输入“上海，周六，两个人，人均100元，下午看展，3小时”，点“整理我的需求”。核对城市、日期、首站开始、预算、人数与可用时长，再看最多两份可行方案。
2. 继续输入“预算改为80元”，点“更新方案”。看“这一轮的调整”：只改变预算，其他条件沿用。点“撤销”回到上一轮，也可用“手动核对”修改。
3. 输入“只去室内，少走路”。室内作为硬条件；“少走路”列在未覆盖要求中。未确认前不能采用；勾选只表示将自行核对，不代表路线已经保证少走路。
4. 核对取舍后采用一份方案。已有正式计划时先确认替换；取消保留原计划。可以在计划中点“继续帮我调整”，接着修改已有条件。
5. 切换“出发速览”，按站查看时间、地址、预留金额和官方信息；可用高德找地点、约搭子或记录打卡。首站开始不含从家到首站的交通，用餐和返程还需另留时间。

不同时段、闭馆日或预算可能导致只有一案或没有结果。页面解释限制，不为保持“有答案”而静默放宽条件；定制只安排所选日期内、22:00 前或正好 22:00 结束的一天。

## 90 秒临时导览

“90 秒体验”会进入一份临时上海双人计划，顶部出现“体验导览”。调整、组队和打卡不写入原有本机记录；点“退出导览”还原进入前状态，刷新重新读取原有记录。90 秒是建议浏览节奏，可按兴趣展开。

| 操作 | 观察重点 |
| --- | --- |
| 看临时计划的时间轴与费用 | 活动、餐饮、交通各有预留；看同行总额、结束时间和时间估算说明 |
| 可选：进入方案定制 | 查看可编辑出行条件，比较最多两案的费用、时长与取舍；采用前确认替换。不展开也可继续用临时计划 |
| 点“试试雨天”，再点“换成室内方案” | 先看替代后的费用、时长与限制，再确认；已有室内活动保留，无可行方案时有说明 |
| 点“分享行程” | 复制链接，在另一标签页预览，或查看本地生成的二维码。本轮只预览即可；接收页的“载入这份行程”是普通操作，会提示替换已有计划 |
| 回到原标签页，点“记录打卡” | 写一句话，可选照片，保存这段临时周末；感受从计划到记录的连续流程 |
| 点“退出导览” | 原有记录恢复，临时调整与打卡结束；已发出的链接不会因此撤回 |

## 再看三条实用路径

**找地点：列表、地图与来源。** 正常模式下在发现页切换“地图”，点地点标记或活动卡，查看位置与详情。12 个真实地点附资料来源，其中 11 个有 OSM 参考坐标；徐汇滨江保留列表展示。地图加载失败可重试或打开高德搜索，仍可继续选择地点。详情中的常规开放、预约说明、规划费用和场次待确认信息各有口径；例如西岸美术馆早到需要等待，周一有常规闭馆限制。查到官方价格后，可回到计划修改对应站点的预留金额，查看全天预算变化。地图用于看位置，时间轴中的转场仍是估算。

**约朋友：用两个独立浏览器完成一次回执。** 请先退出体验导览；这条路径会保存正常记录，可使用两个独立浏览器配置或两台设备，分别扮演发起人和朋友。

1. 发起人在计划页点“约搭子”，选择地点、日期、集合点和人数，创建自己的小队，再点“分享邀请”。示例小队没有真实发起人，不能用于这项操作。
2. 朋友在独立浏览器打开邀请，填写能被朋友认出的昵称，点“确认参加，生成回执”，复制回执链接并自行发回。不要填写电话号码等联系方式。
3. 发起人回到创建小队的浏览器打开回执，核对昵称、活动、日期和人数变化，点“确认导入参加回执”。名单此时才更新，刷新后保留。
4. 可选：朋友在同一浏览器生成撤回回执，发起人打开并确认导入后更新名单。朋友一侧不会实时知道是否已被导入。

这是真实的手动跨浏览器信息传递；没有自动消息、身份核验或实时名单同步。发起人确认的是朋友发来的意向，不是向场馆预约成功。

**留攻略：把自己的经验补进去。** 退出导览后创建正式打卡，在“我的足迹”点“整理成攻略”。已有文字、地点和交通进入可编辑草稿，实际花费标为“待补充”；补充体验后保存，再分享攻略链接或二维码。内容较长时二维码可能退回复制链接，接收者看到的是分享时的快照。

更多入口：发现页展开 **“天气与更多偏好”** 查看城市预报与天气情景；计划可导出日历或文字，页脚可备份与恢复。采用的时长上限随分享和恢复保留；加站导致超时会提示。日历保留完整费用和全部排程警告，存在冲突的安排标为“需调整”，不等于预约成功。

## 看懂几个设计取舍

- **可以继续改，不用重新填。** 多轮输入沿用没提到的条件，展示变化并支持撤销；无法处理的要求保留，不能无声丢失。
- **少给选项，讲清理由。** 定制最多两案；城市、全天预算、时长、室内要求、排除项、当天结束边界与已知开闭馆约束共同生效，兴趣和同行人数影响取舍。
- **费用先讲口径。** 活动列表是单项预留，周末方案包含餐饮交通。真实票价未确认的项目明确标注，规划不超限不等于实际消费保证。
- **信息可查，变化可处理。** 真实地点有来源和核验日期；未知场次不编排成真实活动。天气或底图不可用时仍能用情景和列表完成规划。
- **把行动接起来。** 分享、回执确认、打卡和攻略使用同一批地点与计划；临时导览和正式记录分开，重要覆盖与导入需要确认。

## AI Coding 如何参与

AI Coding 辅助完成需求拆解、产品结构、界面与模块实现，以及代码审查和浏览器检查。迭代从“活动列表”扩展到“全天方案”，再根据实际体验补上费用比较、等待与闭馆约束、来源说明、地图回退、二维码和邀请回执。模块分工后合并到同一站点，源码、自动检查与公开部署分别核对，记录见 [验证记录](VERIFICATION.md)。

运行模式和模型接入状态见[统一说明](../README.md#当前运行模式)。V6 从一次性输入走向“目标、草稿、修订、确认、出发”，但不把对话外观当作智能效果证据。设计参照来自公开产品资料与原题场景，详见 [设计依据](DESIGN.md)；这些过程不等于独立用户研究、个人独立开发或业务增长成果。作品与美团没有官方关联，不提供真实票务、支付或商家预订。

所有正式记录保存在当前浏览器。分享链接可转发且不加密，清除数据前可先备份；二维码只改变链接的传递方式，不增加账号同步或访问控制。
