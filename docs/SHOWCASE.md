# 用 90 秒体验出门啦 · V3

**[打开公开作品](https://leiqingliang.github.io/weekend-city-guide/)**，无需登录。先看首页提案中的活动组合、预计时长和含餐饮交通预留的人均费用，再点 **“90 秒体验”**，直接进入临时示例计划。若想先了解产品设计，可点页首“作品导览”或页脚“作品说明”，再点“开始体验这一个周末”。

这会进入一份临时的上海双人示例计划，顶部出现“体验导览”。体验中的调整、组队和打卡不写入原有本机记录；点“退出导览”会还原进入前状态，刷新则重新读取原有记录。建议的 90 秒路线如下，三步定制可按需展开。

## 推荐体验路线

| 操作 | 看什么 |
| --- | --- |
| 看临时计划的时间轴和费用 | 活动、餐饮和交通合计；同行总额、结束时间及估算说明都能找到 |
| 可选：点“选一份方案” | 依次“选心情 → 定预算 → 留时间”，点“比较我的周末”。比较最多两案的价格、时长、理由和取舍；采用后回到计划。不展开也可继续用示例计划体验 |
| 点“试试雨天”，再点“换成室内方案”并阅读确认提示 | 查看替代后的费用和时长，确认后才替换或减少户外站点；已有室内活动保留，不可行时保留原计划并说明 |
| 点“分享行程” | 复制链接，在新标签页预览。本轮导览只预览即可；“载入这份行程”属于接收页面的普通操作，会提示替换已有计划。接收的是快照，后续修改不会同步 |
| 回到原标签页，点“记录打卡” | 写下一句话，可选上传照片，点“保存这段周末”。这次打卡属于临时体验 |
| 点“退出导览” | 原有本机记录恢复，临时调整与打卡结束；已复制或转发的链接不会因此撤回 |

想继续看完整功能，可以在正常模式中点“定制我的周末”，或从空的“周末计划”直接开始。已有计划时，采用新方案会先确认替换。

## 再多看一分钟

- **同行：** 计划页的“约搭子”直接打开带活动的创建表单，填写日期、集合点与人数；邀请和加入仅在本机演示。
- **天气：** 在发现页展开“有自己的想法？按偏好筛选”，查看“出发前，看一眼天气”。联网失败有明确提示，可以主动改用天气情景。
- **打卡转攻略：** 在“我的足迹”点“整理成攻略”，已有记录、地点与交通会填入可编辑草稿，实际花费标为“待补充”；用户修改并保存后才能作为攻略分享。导览中的新记录不会持久保存，需退出后再创建正式记录。
- **带走计划：** 计划支持“导出到日历”和“下载文字行程”；页脚提供“备份记录”“恢复备份”。

## 设计取舍

1. **少给选项，讲清理由。** 首页先展示具体提案；定制最多给两份结果，让用户比较完整花费、时间与取舍。预算或时间不够时解释原因，不静默放宽条件。
2. **把本地生活流程接起来。** 从发现、计划到约同行、打卡和分享连贯完成；记录先保存在浏览器，暂不建设账号、票务或交易系统。
3. **区分预报、规则和示例。** 天气有来源与失败状态；活动和价格为示例；人数只轻量影响偏好排序；转场与演出时间是规划估算，不代表真实路线或场次。

## AI Coding 如何参与

AI Coding 辅助完成需求拆解、产品与界面设计、模块实现、代码审查和检查。活动推荐、天气、行程、数据保存与展示分工实现，再整合为同一网站；实际行为通过代码检查和浏览器体验核对，版本证据见 [验证记录](VERIFICATION.md)。

应用运行时的推荐和一句话解析使用本地规则，未调用大模型。设计依据来自题目场景，不将示例、检查结果或 AI 协作表述为真实用户研究、个人独立开发或业务增长成果。

## 体验边界

上海、杭州、北京的活动、票价和场次为设计示例，没有真实预约、支付或报名。Open-Meteo 免费预报接口可能限流或不可用；首页与定制的天气情景均有明确标记。日历导出只创建个人计划文件；小队人数不跨设备同步。分享链接内容不加密且可以转发，普通记录保存在当前浏览器，清除数据前可先备份。
